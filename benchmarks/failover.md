# Node-loss survival — measured, not argued

Generated by `./scripts/cluster-demo.sh failover` against a real 3-node CockroachDB
v26.2.5 cluster (`num_replicas = 3`), on 2026-08-04 UTC.

## Why this exists

The sharpest fair criticism of any agentic-memory project is "would this work
identically on single-node Postgres?" Everywhere else this repo answers with an
argument. Here it answers by killing a machine while the agent is reading from it.

The hackathon's own framing is the same point: *an agent whose memory goes offline
doesn't degrade gracefully, it stops.* So the question is whether it stops.

## What this does and does not show

**Shows:** recall kept serving across the loss of a node, and every memory remained
readable afterwards, because each range is Raft-replicated across three nodes. A
single-node deployment cannot do this — losing the node loses the memory.

**Does not show:** multi-region survival, or behaviour under simultaneous loss of a
quorum (2 of 3). Both are out of scope here and neither is claimed.

**Honest caveat:** three containers on one physical machine share a kernel, a disk and
a power supply. This demonstrates the replication and lease-transfer mechanism
correctly; it is not a datacentre-failure test.

**Note on the node list:** `cockroach node status` keeps listing a killed node until
its liveness lease expires, so the kill is confirmed against the container runtime
instead — `node status` output alone would not be evidence.
