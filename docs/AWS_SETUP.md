# AWS setup

Ten minutes, mostly clicking. The goal is a **scoped IAM user whose credentials live only on
your Mac**, which the `aws` CLI reads automatically.

## What NOT to do

- **Do not build a REST API to expose AWS.** A public endpoint holding AWS powers is a
  liability with no upside here. The `aws` CLI reading `~/.aws/credentials` is the standard,
  safer path.
- **Do not create access keys on your root account.** Root keys cannot be scoped and cannot be
  meaningfully revoked without disrupting the whole account. AWS's own guidance is to never
  create them.
- **Do not paste the secret access key into a chat window, a commit, or a screen recording.**
  You type it once into `aws configure`; it lands in `~/.aws/credentials` with `0600`
  permissions. Nothing needs to read it back out.
- **Do not attach `AdministratorAccess`.** `infra/deployer_policy.json` is the exact set of
  actions the scripts call, generated by grepping them.

---

## 1. Lock down the root account (2 min)

Before anything else, in the AWS console:

- **Enable MFA on root.** IAM → Security credentials → Assign MFA device.
- Then stop using root. Everything below uses a separate user.

## 2. Create the deployer user

**Shortcut:** `./infra/bootstrap_deployer.sh` does sections 2–4 for you, given any admin
credential (`aws login` is easiest). It writes the secret straight into `~/.aws/credentials`
without ever printing it. The manual path below is the same thing by hand.

IAM → Users → **Create user**

- User name: `memorystand-deployer`
- Do **not** tick "Provide user access to the AWS Management Console" — this identity is for
  the CLI only, so it does not need a password at all.

On the permissions step choose **Attach policies directly** → **Create policy** → **JSON**, and
paste `infra/deployer_policy.json` with `ACCOUNT_ID` replaced by your 12-digit account number
(top-right of the console, or `aws sts get-caller-identity` once you are configured).

Name it `MemoryStandDeployer`. Attach it to the user.

> The policy grants Lambda/Amplify/SSM/scheduler actions scoped to resources named
> `memorystand*`, plus `bedrock:InvokeModel` on one named inference profile and its two
> underlying foundation models. It cannot touch anything else in your account.
>
> It also, deliberately, cannot modify **itself** — no `iam:CreatePolicy`, no
> `iam:GetPolicy`. An identity that can widen its own permissions is not really scoped.
> Changing it therefore requires an admin credential:
> `AWS_PROFILE=default ./infra/update_deployer_policy.sh`

## 3. Create the access key

Users → `memorystand-deployer` → **Security credentials** → **Create access key** →
**Command Line Interface (CLI)** → acknowledge → Create.

You now see an Access key ID and a Secret access key. The secret is shown **once**.

## 4. Configure it locally

In your terminal — not in chat:

```bash
aws configure
```

Paste the Access key ID, then the Secret access key, then:

- Default region: `us-east-1`  *(Bedrock has the broadest model availability there)*
- Default output format: `json`

Verify:

```bash
aws sts get-caller-identity
```

You should see your account id and `.../memorystand-deployer`. That is the moment the deploy
becomes possible — nothing before it will work, and nothing after it needs the secret again.

## 5. Request Bedrock model access

Bedrock models are opt-in per account. Console → **Amazon Bedrock** → **Model access** →
**Modify model access**, and enable:

- **Anthropic Claude Haiku 4.5** — the agent's reasoning
- **Amazon Titan Text Embeddings V2** — every memory's embedding

For these models approval is usually immediate. Verify from the terminal:

```bash
cd /Users/tom/Documents/GitHub/memorystand
AWS_REGION=us-east-1 .venv/bin/python scripts/spike_bedrock.py
```

That script checks credentials, lists visible models, makes one real embedding call, one real
Converse call, and reports the Titan throughput quota. It fails loudly rather than silently
falling back.

## 6. Set a budget alarm before anything is public

**Bedrock has no free tier**, and this project exposes a public endpoint that calls it. The
shared-secret header on `/ingest` and `/decide` is the first line of defence; a budget alarm is
the second.

Billing → **Budgets** → Create budget → Cost budget → monthly, **$20**, alert at 80% and 100%
to your email. Two minutes, and it means an unexpected bill wakes you up rather than surprising
you at month end.

## Then

```bash
./infra/provision.sh          # CockroachDB Basic cluster, on AWS, via ccloud
./infra/ssm_setup.sh          # DSN + shared secret as SSM SecureStrings
./infra/deploy.sh             # Lambda + Function URL
./infra/deploy_frontend.sh    # dashboard on Amplify
./infra/mcp_setup.sh          # read-only MCP service account
```

`infra/provision.sh` and `infra/mcp_setup.sh` need a separate `ccloud auth login` — that is
CockroachDB Cloud, not AWS.

You can dry-run the riskiest step right now, before any of the above:

```bash
./infra/deploy.sh --package-only
```

That builds the real deployment zip and imports it inside the Lambda runtime image, touching
no AWS at all.

## Afterwards

When the hackathon is judged (after 2026-09-15), delete the access key:

IAM → Users → `memorystand-deployer` → Security credentials → Access keys → Deactivate, Delete.

A credential that exists is a credential that can leak. This one has a known end date.
